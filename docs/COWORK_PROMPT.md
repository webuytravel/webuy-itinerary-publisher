# 在 Cowork 里跑这套流程

给业务同事的交付件。**你不需要会写代码**——写代码的是 Claude,你负责的是判断和签字。

> 这是「今天就能用」的办法,不是最终形态。最终要做成 Skill / MCP 的方案见
> [docs/PRODUCTIZATION.md](PRODUCTIZATION.md)。

---

## 一、开始之前要有的四样

| | 要什么 | 怎么确认 |
|---|---|---|
| 1 | **仓库** | 在 Cowork 里打开 `webuy-itinerary-publisher`(公开仓库,直接 clone) |
| 2 | **Chrome 扩展** | Claude 的浏览器扩展已连接——上传图片和填表都靠它 |
| 3 | **Skybear 登录态** | 你自己在 Chrome 里登录 `travel.webuysg.com` 并保持登录。**Claude 不会、也不该替你输密码** |
| 4 | **行程册 PDF** | 放在你本机能读到的地方 |

不需要任何 API key、数据库密码、`.env`。原因见 [docs/SETUP.md](SETUP.md)。

## 二、把下面这段整个粘进 Cowork

把 `<把 PDF 路径贴在这里>` 换成你的册子路径,其余原样。

```text
帮我把这份行程册做成 Skybear 上的产品草稿:
<把 PDF 路径贴在这里>

开工前请先读 docs/UPLOAD_RUNBOOK.md,按它的顺序走,不要自己发明顺序。
docs/DESIGN.md 记的是每条结论怎么验出来的,遇到反直觉的地方去那里查。

四条红线:
1. 只做到草稿态。Publish for sale 永远不要勾。每次保存前回读 DOM 并截图确认它
   没被勾上——这个框的默认值不可预设。上架我自己点。
2. 产品名不能含 &,要换成 and。选中 Tour Type 后系统会自动把产品名填成带 & 的
   册子标题,那个自动填的值不能信,必须覆盖。
3. 双语字段的中文 key 是 zh 不是 cn。写错会静默失效,保存时才报验证错误。
4. 登录由我做。登录态过期了叫我点一下 Login,不要代填密码。

开工前先在生产后台现查两件事,不要相信任何笔记里的数字:
- 这个 type_code 有没有团期(没有就建不了产品,是硬阻塞,查到没有就停下来告诉我)
- 这个 type_code 有没有已存在的展示产品。如果有而且状态是 Published,停下来问我
  ——那不是编辑模式,那是线上在卖的东西。

需要我做判断的地方停下来问,尤其这两处:
- 你从册子里挑出来的 6 条 highlights,给我看原始的十几条和你的取舍
- 配图审核页出来后我要看过才往下走

做完把 product id 告诉我,并且重新打开编辑页回读核对一遍:产品名、highlights
条数、每天的景点条数、各图片槽位数量、发布框未勾、团期已绑。
```

## 三、过程中你要做的判断

大约三次,每次 Claude 都会停下来等你:

**1. Highlights 怎么取舍。** 册子上有十几条,表单只有 6 格。Claude 会把原始条目和
它的取舍一起给你看。看的是:头部四条有没有把最能卖的东西放上去,餐食两条有没有
漏掉招牌菜。

**2. 配图审核页。** 一个网页,每张图标了来源和判定理由。**重点看外部图源那些**
——它们的典型错法是「主体对、地方不对」:搜西夏陵返回兵马俑,搜驼车返回单峰驼加
南亚服饰。你比 Claude 更清楚这条线路实际长什么样,看着不对就说。

页首如果有红色的「有景点却没有配图」,那是四级图源都没找到合规实拍,要你决定:
留空、你自己提供照片、还是改用当天城市的实拍。

**3. 保存前的截图。** Claude 会给你看发布框没被勾上的截图。确认一眼再让它保存。

## 四、什么时候该停下来找工程

- **查到该 type_code 已经有 Published 的展示产品** —— 那是内容刷新不是新建,
  新建只会造出重复产品
- **没有团期** —— 数据模型上产品不能先于团期存在,要产品组先开团期
- **册子上有必需自费、强制小费、单房差这类条目** —— 当前流程没有字段承载它们,
  别因为表单里没地方放就当它不存在
- **Claude 说浏览器标签页卡死了** —— 这是已知现象(见手册第 5 步),开新标签页
  重来即可;表单在点 Save 之前什么都不写库,重来是安全的

## 五、一个已知的粗糙处

每做一个新产品,Claude 都要往 `bin/make_payload.py` 和 `bin/compose.py` 里加几段
per-product 的配置(6 条 highlights、哪天用哪张图、8 张轮播)。这在 Cowork 里
是自动发生的,你不用管,但它意味着**每个产品都会产生一次代码改动**,需要有人
把这些改动提交回仓库。

这是当前形态的代价,也是 [docs/PRODUCTIZATION.md](PRODUCTIZATION.md) 要解决的
主要问题:把这些编辑决策从源码里搬到数据文件,让它变成配置而不是代码。
